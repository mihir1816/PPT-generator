`teacher-content-gen/`

## Key Decisions
- Model: Qwen3-30B-A3B Q4 (AWQ for vLLM) — with `<think>` block stripping
- Single model (no multi-model strategy for now)
- Inference: vLLM Docker (OpenAI-compatible API, port 8100)
- Backend: Python FastAPI (port 8200) + Celery + Valkey (port 6380) + lifespan + DI via deps.py
- DB: PostgreSQL 16 (port 5433) + SQLAlchemy 2.0 + Alembic
- Vector DB: Qdrant (port 6333)
- File Storage: MinIO (port 9000)
- Embedding: FastEmbed + nomic-embed-text-v2-moe
- Sparse: BM25S (built on-demand at retrieval time, NOT during indexing — process boundary)
- Reranking: FlashRank
- Chunking: Parent-Document hierarchical (512 tokens, 50 overlap)
- Streaming: SSE via sse-starlette (backend) + @microsoft/fetch-event-source (frontend, POST support)
- Frontend: React + Vite + TailwindCSS (port 3000)
- Export: python-pptx
- OCR: Tesseract + pytesseract (NOT PaddleOCR — too heavy)
- Retrieval data: stored in Deck.retrieval_json (DB), NOT Redis with TTL
- Undo: outline + slide snapshots in FeedbackRound
- No web search
- No concurrent user optimization
- Two feedback loops: syllabus (before RAG) + slides (after content gen)

## Known Issues / Deviations From Session Docs
- `minio/minio:latest` is no longer pullable from Docker Hub (access denied) — switched to
  `quay.io/minio/minio:latest` in `docker-compose.yml`.
- Debian `trixie` (python:3.12-slim base) dropped `libgl1-mesa-glx` → renamed to `libgl1` in Dockerfile.
- qdrant's official image has no `curl`/`wget`, so its healthcheck uses a bash `/dev/tcp` TCP-connect
  check instead of `curl http://localhost:6333/healthz`.
- `qdrant-client` pinned to `>=1.13.0,<1.15.0` to stay within 1 minor version of the qdrant server (v1.14.0)
  and avoid a client/server compatibility warning.
- **`docling` moved from a hard dependency to an optional extra** (`pip install -e ".[docling]"`).
  Installing it by default pulled the full CUDA-enabled torch + NVIDIA toolkit (4-5GB+) as a transitive
  dependency, which is unnecessary for this CPU-only FastAPI/Celery container (vLLM is the sole GPU
  consumer and runs in its own container) and made every rebuild extremely slow on a bandwidth-limited
  dev machine. `services/parsers/pdf_parser.py::_try_docling()` already degrades gracefully (falls back
  to pdfplumber-only results) when docling isn't installed, so this has no functional impact on the
  documented pdfplumber-first parsing strategy.
- Dockerfile installs deps in a layer keyed only on `pyproject.toml` (with a stub `src/app/__init__.py`
  to satisfy setuptools' package-discovery at install time), then `COPY . .` after — so editing app code
  no longer invalidates/re-downloads the dependency layer on rebuild (the session doc's original order
  copied full source before `pip install -e`, which broke both setuptools discovery and Docker caching).
- `celery_app.autodiscover_tasks(["app.tasks"])` (as read literally from the session flow) does not find
  tasks — Celery's autodiscovery looks for a `tasks` submodule *inside* each listed package, so passing
  `app.tasks` itself made it look for a nonexistent `app.tasks.tasks`. Fixed to `autodiscover_tasks(["app"])`
  plus explicit task imports in `src/app/tasks/__init__.py` (submodules aren't auto-imported by a package
  import alone).

## Known Limitations / Deferred
- No concurrent user optimization (single-tenant design)
- No web search augmentation for RAG gaps
- `storage.py` reads entire uploaded file into memory (acceptable for documents)
- Slide generation marks deck COMPLETED even if some slides fail (partial success)
- BM25 sparse index rebuilt per retrieval (not persisted)
- FlashRank/embedding errors in `rag.py` fall back gracefully but are not surfaced to user
- `feedback.py` delete action can remove title slide without automatic re-insertion
- No per-slide error handling in PPTX export (single slide failure fails entire export)
- Fuzzy matching threshold for chunk IDs in `slide_outline.py` is 0.3 (permissive)
